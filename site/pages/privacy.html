Privacy Policy

Last updated: 29 October 2026

Zubi is built so that your reminders, calendars and notes stay under your control. There is no Zubi account and no Zubi server: the app runs on your Mac and answers only the devices you connect to it. This policy covers the Zubi app, the zubi command-line client, and this website.

The Zubi app

With your permission, the app reads Reminders, Calendar and Notes on your Mac, and adds and edits items in them where you allowed it. It serves only the lists, calendars and folders you shared, makes changes only in those you set to Read & Write, and answers only requests carrying the API key it generated. It never deletes anything. We never receive any of this data.

Stored on your Mac, and nowhere else:

  • The keys you created for your devices, with their names, in your Keychain, and when each was last used.
  • The activity log: the last 500 things created or edited through the API, with the time, the key’s name and the item’s title, in ~/Library/Application Support/de.fa-krug.zubi/activity.json. Clear under Settings › Activity deletes it.
  • Your settings, including which items you share and the address the server listens on.
  • A short list of recent requests, held in memory while the app runs and shown in the menu.
  • The result of the last update check, in the app’s cache folder.

Connections the app makes

  • Your devices. The app answers HTTP requests from the devices you connect to it. Whatever those devices or programs do with the data is up to you and them.
  • GitHub, for updates. Once a day the app asks GitHub’s API for the list of Zubi releases, and when you choose to update it downloads the new version from GitHub. GitHub, Inc. sees your IP address and a user agent naming Zubi, as it does for any visitor; see the GitHub Privacy Statement. You can switch the daily check off under Settings › General.
  • The API docs page. /docs, served by your Mac, loads Swagger UI from the jsDelivr content network into the browser that opens it, so jsDelivr sees that browser’s IP address. Nothing else in Zubi uses it, and the page only loads when you open it.
  • Your local network. While Zubi serves on all interfaces, it announces itself on the local network with Bonjour, giving its name, port and version, so the zubi command can find it. It announces nothing while it listens only on your Mac or on one address.
  • Calendar subscriptions. A subscription link contains a key, so the calendar app you give it to stores the key and sends it with every refresh. Only Read keys work in a link.
  • Notes.app. Zubi reads and, where allowed, writes Notes by scripting Notes.app on the same Mac. This stays on your Mac; changes then sync through iCloud as any change you make in Notes would.

The command-line client

zubi connects only to the Zubi address you configure. It stores that address and the key in a settings file readable only by your user account, and sends nothing anywhere else.

The exception is zubi relay, which you run yourself, on a machine you choose, so a Mac and its clients on different networks can reach each other. To get and renew its certificate, it asks a STUN server run by Cloudflare or Google for its network’s public IP address, and requests the certificate from Let’s Encrypt (Internet Security Research Group, USA), which connects back to that address to check it. Both learn the address of the machine running the relay. Like every publicly trusted certificate, it is recorded in public Certificate Transparency logs, so the address or domain it certifies becomes public. Whoever runs a relay can see which addresses connect to it, when, and how much they send; the relay holds no key to your data and logs no client addresses. Zubi runs no relay of its own.

Die Zubi-App

Mit Ihrer Erlaubnis liest die App Erinnerungen, Kalender und Notizen auf dem Mac und legt dort, wo Sie es erlauben, Einträge an oder ändert sie. Sie gibt nur die Listen, Kalender und Ordner heraus, die Sie freigeben, ändert nur in denen, die Sie auf „Read & Write“ gestellt haben, und antwortet nur auf Anfragen mit dem von ihr erzeugten API-Schlüssel. Sie löscht nie etwas. Wir erhalten keine dieser Daten.

Auf dem Mac gespeichert, und nirgends sonst:

  • Die Schlüssel, die Sie für Ihre Geräte anlegen, samt Namen, im Schlüsselbund, und wann jeder zuletzt benutzt wurde.
  • Das Aktivitätsprotokoll: die letzten 500 über die API angelegten oder geänderten Einträge mit Zeit, Name des Schlüssels und Titel, in ~/Library/Application Support/de.fa-krug.zubi/activity.json. Clear unter Settings › Activity entfernt es.
  • Ihre Einstellungen, darunter die freigegebenen Elemente und die Adresse, auf der der Server lauscht.
  • Eine kurze Liste der letzten Anfragen, nur im Arbeitsspeicher, solange die App läuft, und im Menü angezeigt.
  • Das Ergebnis der letzten Update-Prüfung, im Cache-Ordner der App.

Verbindungen der App

  • Ihre Geräte. Die App beantwortet HTTP-Anfragen der Geräte, die Sie mit ihr verbinden. Was diese Geräte oder Programme mit den Daten tun, liegt bei Ihnen und ihnen.
  • GitHub, für Updates. Einmal täglich fragt die App bei der GitHub-API die Liste der Zubi-Versionen ab, und wenn Sie ein Update wählen, lädt sie die neue Version von GitHub. GitHub, Inc. sieht dabei Ihre IP-Adresse und eine Kennung mit dem Namen Zubi, wie bei jedem Besucher; siehe die Datenschutzerklärung von GitHub. Die tägliche Prüfung lässt sich unter Settings › General abschalten.
  • Die API-Dokumentation. /docs, vom eigenen Mac ausgeliefert, lädt Swagger UI aus dem Content-Netzwerk jsDelivr in den Browser, der die Seite öffnet; jsDelivr sieht dabei dessen IP-Adresse. Sonst nutzt Zubi jsDelivr nicht, und die Seite lädt nur, wenn Sie sie öffnen.
  • Ihr lokales Netzwerk. Solange Zubi auf allen Schnittstellen antwortet, kündigt es sich per Bonjour im lokalen Netzwerk an, mit Name, Port und Version, damit der Befehl zubi es findet. Lauscht es nur auf dem Mac oder einer einzelnen Adresse, kündigt es nichts an.
  • Kalender-Abonnements. Ein Abo-Link enthält einen Schlüssel; die Kalender-App, der Sie ihn geben, speichert ihn und sendet ihn bei jeder Aktualisierung. In einem Link funktionieren nur Schlüssel mit Lesezugriff.
  • Notizen-App. Zubi liest Notizen und schreibt sie, wo erlaubt, indem es die Notizen-App auf demselben Mac steuert. Das bleibt auf dem Mac; Änderungen werden anschließend wie jede eigene Änderung über iCloud synchronisiert.

Der Kommandozeilen-Client

zubi verbindet sich nur mit der eingerichteten Zubi-Adresse. Adresse und Schlüssel speichert er in einer Einstellungsdatei, die nur Ihr Benutzerkonto lesen kann, und sendet nichts an andere Stellen.

Die Ausnahme ist zubi relay, das Sie selbst auf einem Rechner Ihrer Wahl betreiben, damit ein Mac und seine Clients in verschiedenen Netzen einander erreichen. Um sein Zertifikat zu beziehen und zu erneuern, fragt es einen STUN-Server von Cloudflare oder Google nach der öffentlichen IP-Adresse seines Netzes und beantragt das Zertifikat bei Let’s Encrypt (Internet Security Research Group, USA), das sich zur Prüfung mit dieser Adresse verbindet. Beide erfahren dabei die Adresse des Rechners, auf dem das Relay läuft. Wie jedes öffentlich vertrauenswürdige Zertifikat wird es in öffentlichen Certificate-Transparency-Logs verzeichnet; die zertifizierte Adresse oder Domain wird damit öffentlich. Wer ein Relay betreibt, sieht, welche Adressen sich wann verbinden und wie viel sie senden; das Relay hat keinen Schlüssel zu Ihren Daten und protokolliert keine Client-Adressen. Zubi selbst betreibt kein Relay.
