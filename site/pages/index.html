Your Mac’s reminders, calendars and notes, on everything else.

Zubi is a free menu bar app that serves the Reminders lists, calendars and Notes folders you choose over a small HTTP API. A Raspberry Pi on the wall, a Linux laptop, a script or an AI agent can read them, and add and edit them where you allow it. The data never leaves your Mac for anyone else’s server.

Where you can use it

Anything that can make an HTTP request can read what you share: plain JSON, described in OpenAPI. For terminals and agents there is zubi, a small command-line client for macOS, Linux and Windows.

  • A Raspberry Pi display

    Put today’s events and the shopping list on a screen by the front door or the fridge. The Pi reaches your Mac through a relay, end-to-end encrypted, an SSH tunnel or your Tailscale network.

    zubi events
zubi reminders --list Groceries

  • Home Assistant and Node-RED

    A REST sensor turns your reminders into a number on a dashboard, or a trigger for an automation when something is overdue.

    sensor:
  - platform: rest
    name: Reminders due today
    resource: http://mac.local:8787/api/reminders?due=today
    headers:
      Authorization: !secret zubi_bearer
    value_template: "{{ value_json.reminders | count }}"

  • AI agents

    Let Claude Code, Codex or any agent with a shell read your schedule, and, in the lists and calendars you open for writing, add events and tick off reminders. --json prints the API’s answer as-is, and every failure has its own exit code.

    zubi events --from 2026-11-02 --to 2026-11-06 --json

  • Scripts and cron jobs

    A morning summary by email, a reminder count in your shell prompt, or a backup of a Notes folder as plain text.

    zubi reminders --due overdue --json \
  | jq -r '.reminders[].title'

  • Linux and Windows

    Your Apple calendars and reminders in a terminal on the computers Apple doesn’t make apps for.

    zubi calendars
zubi notes --folder Recipes

  • Your own app

    Every endpoint is described in an OpenAPI document, so you can generate a client in any language, or read the API reference.

    curl -H "Authorization: Bearer $ZUBI_KEY" \
  http://127.0.0.1:8787/api/calendars

Set it up in three steps

About three minutes on your Mac. Nothing is shared until step two, and only what you choose.

  1. Install

    Download Zubi, unzip it and move it to Applications. Open it, and its icon appears in the menu bar. It is signed and notarized, and keeps itself up to date.

  2. Choose what to share

    Click the menu bar icon, then Settings…. Under Reminders, Calendars and Notes, click Grant Access, then set each list, calendar and folder to Read, or to Read & Write if your devices may also add and edit there.

  3. Make your first call

    Under Keys, click Copy Command and run it in Terminal. You get your shared events back as JSON.

    curl -H "Authorization: Bearer <key>" \
  http://127.0.0.1:8787/api/events

Reading from another device? At first Zubi only answers on your Mac. From any network, go through a relay: turn it on under Settings › Server and run zubi pair with a key’s pairing code. Or tunnel to it with ssh -N -L 8787:localhost:8787 you@mac.local, or bind it to your Tailscale address.

Then install the command-line client on that device, or call the API directly.

What Zubi shares, and what it doesn’t

Nothing until you choose

Every list, calendar and folder starts Off, which answers as if it didn’t exist. Read shares it; only Read & Write lets your devices add and edit there. Nothing is ever deleted.

A key on every request

Each call needs the API key generated on your Mac and kept in its Keychain. You can replace it with one click.

Your Mac only, by default

Zubi listens on 127.0.0.1 until you decide otherwise, so nothing on your network can reach it by accident.

No cloud, no account

There is no Zubi server. The app talks to your devices, and once a day to GitHub to check for updates, which you can switch off.
