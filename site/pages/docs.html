Documentation

Zubi on your Mac shares the reminders, calendars and notes you choose. The zubi client on your other devices uses them, from anywhere.

Get started

  1. On your Mac: download Zubi, move it to Applications and open it. It connects on its own (its menu shows a green dot) and starts with your Mac from now on. (macOS 14 or later.)
  2. Choose what to share: in Zubi’s Settings, under Reminders, Calendars and Notes, click Grant Access, then set what you want to Read, or Read & Write if your devices may also add and edit. Everything else stays private.
  3. On your device: install the client and run it. 
    curl -fsSL https://zubi.fa-krug.de/install.sh | sh
zubi
    Paste the pairing code from Zubi’s menu bar icon › Copy Pairing Code. Done: it stays connected from now on.

The install line works on Linux, a Raspberry Pi and macOS. Alternatively: brew install fa-krug/tap/zubi, or on Windows with Scoop: scoop bucket add fa-krug https://github.com/fa-krug/scoop-bucket, then scoop install fa-krug/zubi.

Use it

zubi on its own shows whether everything is connected:

zubi
✓ Paired as "Default", through wss://relay.fa-krug.de
✓ The zubi-client service keeps the connection
✓ Your Mac answers

Then:

zubi reminders
zubi events
zubi notes
zubi reminders add "Buy milk" --list Groceries
zubi watch

zubi watch prints a line whenever something changes, handy for a display. zubi help lists every command. For scripts, add --json.

AI assistants: in Claude Code, run claude mcp add zubi -- zubi mcp. In Claude Desktop, add this to claude_desktop_config.json:

{ "mcpServers": { "zubi": { "command": "/usr/local/bin/zubi", "args": ["mcp"] } } }

More devices

Each device can share the first code, or get its own: in Settings › Clients, click Add Client… and pair the device with that code. With its own code, you can remove one device later without touching the others.

If something doesn’t work

Run zubi. It shows what isn’t working:

“Your Mac doesn’t answer”
The Mac has to be on and logged in, with a green dot in Zubi’s menu. To keep it from sleeping, turn on Keep this Mac awake in Settings › General.
“Your Mac refused the key”
That device was removed or got a new code. Copy its code again and run zubi pair -.
A list, calendar or folder is missing, or can’t be changed
Check its setting in Zubi’s Settings: Off hides it, Read can’t be changed.
Notes doesn’t work
Allow Zubi to control Notes in System Settings › Privacy & Security › Automation.

Privacy and security

  • Nothing is shared until you choose it, and Zubi never deletes anything.
  • Everything between your Mac and a device is encrypted with that device’s code. The relay in between only passes it on and can’t read it.
  • No account, no tracking. Treat a pairing code like a password.

Details are in the privacy policy. To report a vulnerability, see the security policy.

Your own relay

Optional. Out of the box, your Mac and your devices meet at Zubi’s relay, relay.fa-krug.de, and you don’t need anything else. The relay can’t read your data either way, but if you’d rather not depend on it, run your own: it’s the same zubi command, with relay.

Which one?

Pick the first that fits. Each ends with a wss:// address for your Mac.

ScenarioYou needGood when
Cloudflare TunnelA machine at home, a domain on CloudflareYou can’t or don’t want to change your router
At home, port forwardedA machine at home, access to your router, a public IPv4 addressYou want no third party at all
On a serverA rented server (VPS) with a public addressYou have one already
Behind your web serverA server already running Caddy or nginx with HTTPSYou host other sites there
Free hostingA free Render accountYou have no machine that is always on

A machine at home can be a Raspberry Pi, even the one that shows your reminders; the relay needs almost nothing. Install zubi on it first:

curl -fsSL https://zubi.fa-krug.de/install.sh | sh

Cloudflare Tunnel

No router changes, and your home address stays hidden. You need a domain on Cloudflare and a tunnel with cloudflared running on the machine.

  1. Run the relay where the tunnel can reach it: 
    zubi relay --behind-tls-proxy --listen 127.0.0.1:8080 --install-service
  2. In the Cloudflare dashboard, open your tunnel and add a public hostname, such as relay.example.com: service type HTTP, URL 127.0.0.1:8080. Write 127.0.0.1, not localhost, which may reach a different program.
  3. Check it: https://relay.example.com/health answers ok.

Your relay’s address: wss://relay.example.com.

At home, port forwarded

Nobody else involved: the relay gets its own certificate from Let’s Encrypt for your public IP address and renews it by itself.

  1. On your router, forward TCP port 443 to port 443 of the machine.
  2. Run the relay: 
    zubi relay --install-service
journalctl -u zubi-relay        # shows: Relay ready: wss://203.0.113.7

Your relay’s address is the one it shows. Two things to know: your internet connection needs its own public IPv4 address (some mobile and fibre connections share one; ask your provider), and if your address changes, a free DuckDNS name keeps it stable: add --domain yourname.duckdns.org, and the address becomes wss://yourname.duckdns.org.

On a server

The simplest, if you rent a server (any VPS, or Oracle Cloud’s free tier) with a public address and port 443 free:

zubi relay --install-service
journalctl -u zubi-relay        # shows the relay's address

It certifies the server’s IP address by itself. With a domain pointing at the server, add --domain relay.example.com for wss://relay.example.com.

Behind your web server

If Caddy or nginx already serves HTTPS on the server, let it pass a hostname on to the relay:

zubi relay --behind-tls-proxy --listen 127.0.0.1:8080 --install-service

For Caddy:

relay.example.com {
    reverse_proxy 127.0.0.1:8080
}

For nginx, inside the server block for that hostname:

location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

Your relay’s address: wss://relay.example.com.

Free hosting

No machine of your own: Render’s free web service runs the relay. Choose New › Web Service, public Git repository https://github.com/fa-krug/zubi, and:

Health Check Path (under Advanced)/health

Your relay’s address is the service’s URL with wss://, such as wss://zubi-relay.onrender.com. Free services sleep when idle; your connected Mac keeps it awake. Deploy again to get a newer version.

Switch to it

  1. On your Mac, in Zubi’s Settings › Connection, turn on Use my own relay, enter your relay’s wss:// address and click Apply. The dot turns green once the Mac is connected; if not, the message under it says why.
  2. Pair each device again, since a pairing code names its relay: copy the code from Zubi’s menu, and on the device run zubi pair - and paste it.

To go back, turn Use my own relay off and pair again.

Keep it running

--install-service runs the relay in the background on Linux, starts it at boot and restarts it after a failure. To change its options, run the command again with the new ones.

systemctl status zubi-relay         # is it running?
journalctl -u zubi-relay -f         # what it does
sudo systemctl restart zubi-relay   # after updating zubi
zubi relay --uninstall-service      # remove it

The relay keeps no data. It logs when a Mac connects or leaves, never the addresses of your devices.
